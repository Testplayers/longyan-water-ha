## 二、怎么改代码 → 怎么部署到 HA

代码在**本机**编辑，**改完必须部署到 HA** 才生效。三步法：

```bash
# 1) 本机改代码（vscode 打开 custom_components/longyan_water/xxx.py）

# 2) 部署（覆盖式，会先删旧目录）
python tools/deploy.py

# 3) 等 HA 起来（约 1-15 分钟，HAOS 慢）
#    验证日志
```

部署脚本做的事：打包 `custom_components/longyan_water` → SSH 流式写 tar.gz →
远程 `rm -rf` 旧目录 → 解压 → `ha core restart`。

### 验证部署成功

```bash
# HA 主机上
docker logs homeassistant 2>&1 | tail -50 | grep -i longyan_water
ls /homeassistant/custom_components/longyan_water/
```

HA 网页：**开发者工具 → 状态**，搜 `zi_lai_shui`，看 8 个实体是否在线。

> 💡 只改 `sensor.py` 这类实体代码时，可以在 HA 里
> **设置 → 设备与服务 → 该集成 → ⋮ → 重新加载**，比重启快得多。
> 但改了 `manifest.json`、`const.py` 里被 import 的常量，还是建议重启。

## 三、场景 1：网厅接口改了

**症状**：实体变 unavailable，日志里出现 `查询户号失败(404)`、`登录失败(500)`、JSON 解析错误等。

**原因**：网厅前端改版，接口路径或参数格式变了。

**修复步骤**：

1. **重新抓包**（详见 [02 · 接口原理](02-接口原理.md#自己重新抓包网厅改版时用)）
   - F12 → Network → 登录 + 查账单 → 找 `login.json` / `queryUserMeterList` 请求
   - 对比 `requestPara` 的参数名和返回 JSON 的字段名是否和现有代码一致
2. **改代码**，通常只改这几处：

| 变了什么 | 改哪里 |
|---|---|
| 接口路径（URL） | `const.py` → `LOGIN_URL` / `CAPTCHA_URL` / `METER_LIST_URL` |
| 公共参数（如 `appVersion`、新增字段） | `const.py` → `_fixed_params()` |
| 请求体包装方式（不再是 `requestPara=JSON`） | `api.py` → `_post()` |
| 返回字段名（如 `balance` 改名） | `sensor.py` 各 `native_value` + `entity.py` |
| 状态码含义变化 | `api.py` → `login()` / `meter_list()` 里的 status 判断 |

3. 部署（`python tools/deploy.py`）
4. **手动触发一次**验证：HA 里重载集成，看实体是否恢复有值

**调试小技巧**：先在本地直接用 python 打请求，比在 HA 里反复部署快得多：

```python
# tools/probe.py（自建） 或直接 python -c
import asyncio, aiohttp, json, hashlib, time
BASE = "https://service.fjlyzls.com"
FIXED = {"waterCorpId": 3, "UNID": "", "areaId": 0,
         "accountType": "XJ", "apiType": "PC", "appVersion": "1.0.2"}

async def main():
    async with aiohttp.ClientSession() as s:
        # 1. 拿验证码（保存图片人工看）
        ts = str(int(time.time() * 1000))
        async with s.get(BASE + "/iwater/nt/validateCode.json",
                         params={"timestamp": ts}) as r:
            open("captcha.png", "wb").write(await r.read())
        code = input("看图输入验证码: ")
        # 2. 登录
        p = dict(FIXED, token=None, userName="手机号",
                 password=hashlib.md5("密码".encode()).hexdigest(),
                 code=code, timestamp=ts)
        body = ("requestPara=" + json.dumps(p, ensure_ascii=False)
                ).replace("+", "%2B").replace("&", "%26")
        async with s.post(BASE + "/iwater/nt/wt/login.json", data=body) as r:
            print(await r.json(content_type=None))

asyncio.run(main())
```

## 四、场景 2：验证码样式变了

**症状**：配置集成时一直进「人工输入验证码」界面；或自动重登老是失败。

**原因**：网厅换了验证码字体/颜色/干扰线，现有模板匹配不上。

**修复步骤**：

1. 抓一张新验证码图片（上面 probe 脚本第一步会存成 `captcha.png`）
2. 看看它的字体风格是否还是**彩色字符 + 无干扰线**
   - 相同风格 → 直接跑 `python tools/gen_captcha_templates.py` 重新生成模板（会换更全的字体变体），把生成的 JSON 覆盖 `custom_components/longyan_water/captcha_templates.json`
   - 风格大变（有干扰线/扭曲/粘连）→ 模板匹配方案基本失效，需要换 OCR 方案：
     - 简单方案：接第三方打码平台 API（付费）
     - 本地方案：`ddddocr`（`pip install ddddocr`，它是为这类中文字符验证码训练的，对本场景效果好很多）
3. 换 `ocr.py` 的思路：

```python
# 用 ddddocr 替换 ocr.solve_captcha 的实现
import ddddocr
_ocr = ddddocr.DdddOcr(show_ad=False)
def solve_captcha(jpeg: bytes) -> str:
    return _ocr.classification(jpeg).upper()
```

> 用 ddddocr 的话记得在 `manifest.json` 的 `requirements` 里加 `"ddddocr"`，
> 它是 C 扩展，HA 容器里可能装不上（架构/编译问题），装不上就用「人工输入兜底」顶着。

4. 部署 + 重启，重新走一次配置流程验证

## 五、场景 3：HA 升级后不兼容

**症状**：HA 大版本升级后集成加载失败，日志报 `ImportError` / `KeyError` / `TypeError`。

**已知踩过的坑**（后人都可能再遇到）：

| 报错 | 原因 | 修法 |
|---|---|---|
| `ImportError: cannot import name 'CURRENCY_YUAN'` | HA 移除了该常量 | 用字符串 `"CNY"`（本项目已改好） |
| 配置条目 `KeyError: 'subentries'` | 新版 storage 格式要求 | 条目里补 `"subentries": []`（UI 添加的不会有） |
| `UpdateFailed` / coordinator 签名变化 | HA 内部 API 变动 | 对照 HA 官方文档更新 `coordinator.py` |
| 实体唯一 ID 冲突 | 实体命名规则变化 | 清掉旧实体注册表条目后重加 |

**排查入口**：

```bash
docker logs homeassistant 2>&1 | grep -A 15 'longyan_water' | head -60
```

`manifest.json` 里可以声明兼容的最低版本：

```json
{ "version": "1.0.1" }
```

## 六、场景 4：密码/账号变了

不支持界面改密码，直接：

1. 设置 → 设备与服务 → 删除该集成
2. 重新「添加集成」，输入新账号

或者直接改 storage（**需要先 `ha core stop`**，否则会被覆盖）：

```bash
ha core stop
python3 - <<'EOF'
import json
p = "/homeassistant/.storage/core.config_entries"
d = json.load(open(p))
for e in d["data"]["entries"]:
    if e["domain"] == "longyan_water":
        e["data"]["password"] = "新密码"
        e["data"]["username"] = "新手机号"
json.dump(d, open(p, "w"), ensure_ascii=False, indent=2)
EOF
ha core start
```

## 七、版本号与发布

改完代码要**同步升版本号**，便于回滚时区分：

- `custom_components/longyan_water/manifest.json` → `"version": "1.0.1"`
- 顺手在 `docs/06-更新与维护.md` 或 `CHANGELOG.md` 记一句改了什么

发布到 GitHub（本机，用 token 走 REST API，**无需安装 git**）：

```bash
# token 放环境变量（推荐）
set GH_TOKEN=ghp_xxx            # Windows CMD
$env:GH_TOKEN="ghp_xxx"         # Windows PowerShell
export GH_TOKEN=ghp_xxx         # Linux / macOS

python tools/publish.py --msg "fix: 适配网厅 2026-10 改版"
```

`tools/publish.py` 做的事：

1. 校验 token、确认仓库存在（不存在则创建）
2. 把本地**所有文件**通过 blob API 上传
3. 用「不带 base_tree 的新 tree」建一次提交 → **远端多余文件会自动消失**（以本地为准）
4. 更新 `main` 分支

> token 权限：Classic token 勾 `repo`；Fine-grained token 需要
> `Contents: Read and write`（首次建仓库还需 `Administration: Read and write`）。

打 Release：GitHub 网页 → Releases → Draft a new release → 标签 `v1.0.1` → 描述改动。
打上 Release 后，别人就能直接下载 zip（虽然 HAOS 用户还是建议用 `deploy.py` 本机上传）。

## 八、回滚与备份

**部署前备份**（强烈建议，尤其是改完不确定能不能跑时）：

```bash
# HA 主机上，部署前先备份当前版本
cp -r /homeassistant/custom_components/longyan_water \
      /homeassistant/custom_components/longyan_water.bak-$(date +%Y%m%d-%H%M%S)
```

**回滚**：

```bash
ha core stop
rm -rf /homeassistant/custom_components/longyan_water
mv /homeassistant/custom_components/longyan_water.bak-20260921-220000 \
   /homeassistant/custom_components/longyan_water
ha core start
```

**本机备份**：把 `custom_components/longyan_water` 提交到 git 仓库（本仓库本身就是备份），
每次改完 commit 一次，出问题 `git checkout` 回上一个版本即可。
